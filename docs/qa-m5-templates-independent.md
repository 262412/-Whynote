## Q-27／P2：按时渲染回执被异步复查误判过期

契约：M5-2b「展示和响应」要求服务端按回调到达时刻判断期限，同时在事务内核对权限、版本与当前动作；PRD 当前 M5-2 条目也将 60 秒期限绑定入口收到时间。已到达的渲染事实不能因为后续服务端等待而变成未渲染。

操作（受控墙钟，实际 Action／事件事务，无数据库查询替身）：

1. 点踩创建动作及 Outbox，生成建议；生成时间 `1788220800.0`，截止 `1788220860.0`。
2. 返回完整有效 binding，回调到达为 `1788220859.5`（第 59.5 秒）。
3. 后续 `_owned_chat` 权限复查模拟耗时 1 秒，时间到 `1788220860.5`。
4. 读取同一动作的真实 SQLite 事件及 Outbox。

**预期：** 保存一次有效渲染回执；60 秒之后的新响应仍应拒绝。事务内继续复核撤权、换版、撤销和停用，不能用早到时间绕过这些限制。

**实际：** 返回 `suggestion.result=superseded`；事件仅有 `negative_feedback_action_recorded`、`m52_suggestion_generated`，`m52_render_reported=0`。动作仍 active，Outbox=1。报告会把这次已返回回执的展示列为缺失；此用例没有用户确认，因此没有响应丢失的证据。

根因：`integrations/openwebui/template_action.py` 的 `receive()` 已返回 `(value, received_at)`，渲染分支用 `rendered, _` 丢弃时间，再等待 `current()`；`src/whynote/suggestions.py:render()` 在事务内调用 `_current()` 时改用当前墙钟。响应分支已经传递 `server_received_at`，渲染分支未传递。

复现：

```powershell
uv run --no-sync pytest tests/test_templates_independent.py -q
uv run --no-sync pytest tests qa/test_s0_regressions.py qa/test_manual_v1_acceptance.py -q
```

原断言分别得到 22 通过／1 失败、675 通过／1 失败，不使用 skip、xfail 或特判。相邻对照：59.5 秒回执且无延迟可以入库；60 秒整及 60.5 秒回执均拒绝。说明失败由宿主复查跨越截止时间引起。

责任与下一轮：原 PR 后端／客户端负责人修复时间传递；QA 原样复跑，并补数据库等待跨期限、到达后撤权／撤销／换版／停用的渲染用例。产品／数据确认渲染分母口径，非作者批准与适用结果签署仍须完成。

## 本轮浏览器与数据库对账

Chrome 扩展连接返回 `nodeRepl.fetch request failed`，切换内置浏览器后实际完成以下操作。首个 AX click 未触发操作，改用有焦点的键盘操作并逐步核验页面。

1. 点踩：看到两条固定建议、直接问题和回答原文，以及“合成模型建议，未确认；未运行代码”提示，无默认确认。
2. 确认「改变了需保留的接口」，更正为「未按指令」，完成：返回 `confirmed`。
3. 同一按钮撤销：返回 `retracted`，当前研究原因清空，历史确认保留。
4. 再次点踩，选择「都不是」：弹出常规菜单；选择「事实有误」提交，返回 `reason_submitted`。
5. 读取报告：2 生成／2 可展示／2 渲染／2 有效响应组／1 历史确认；yes=1、correct=1、none_matched=1、撤销=1，3 条 client_reported 计时。更正不重复增加响应组分母。

数据库共 12 条事件：2 动作、1 撤销、2 建议生成、2 渲染、3 响应、1 常规展示、1 人工选因；Outbox=3（两次动作及一次撤销）。固定 as_of 重读与浏览器保存报告完全一致，数据库 SHA-256 不变；事件和报告无虚构问答正文、配置密钥。
