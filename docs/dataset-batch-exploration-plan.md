## 1. 一条路线、两个运行用途

**来源与本机使用范围登记 → 下载三个固定数据文件 → 统一输入 → 本机 Laya 批量运行 → 查看诊断报告 → 正式评测批次准入 → 探索审阅 → 理由包冻结 → 新留出集 → 盲标复标 → 冻结运行 → 判定通过与否。**

下载前的登记仅确认来源/许可限制、文件身份、用途和本机存储边界；报告后的准入决定哪些材料适合正式质量评测。二者分开，不能先运行后补使用授权，也不要求首次探索先完成人工逐条审阅。

- 当前优先交付 `explore`：无需人工标签，自动报告模型做了什么、多少材料可处理、哪里失败；可以修改理由包后以新 run 比较。
- 后续保留 `evaluate`：需要冻结协议、人工标签和未暴露的留出组，才计算正确性及通过/不通过。既有 `controlled_replay`、`self_review` 与历史报告保留，不将它们的字段设为 explore 必填。
- 本次不要求探索30、验证60、180槽位、任务/中文配额、48小时复标或签署才能首次探索。旧 D-20 参数只保留在后置正式评测协议中；若范围/计时/策略改变，正式评测前重新定版，不事后套阈值。
- 默认用现有候选 C（任务理由＋通用理由＋回退）；A/B/C 可选诊断，不强制三倍运行，不开展 TypeSafe/Laya 排名。
- 自动结果保持 `model_inferred_unconfirmed`。数据集原反馈、自动标签、模型输出、本人标注和独立 gold 分层；没有标签时正确率、真实理由覆盖和错误归因率显示 NA，不生成质量 PASS。

## 4. 自动入口、执行与恢复

以下是待实现接口要求，不是现在可复制执行的命令：统一入口提供 `prepare / run / report / resume`，支持选择 `helpsteer3,wildfb,wildfeedback`、固定文件manifest、模型目录、CUDA设备、方案、每源数量或all、seed和新输出目录。

- 数量可配置；默认先每源100个源记录的有界冒烟，确认计数/预算与运行后，支持每源1000及显式all。100/1000是工程放量阶梯，不是人工标注配额或质量样本量；不足则报实际量，不补重复记录。
- 初版串行：GPU worker=1，模型 batch size=1；批量指大量记录连续处理，不默认并发占满显卡。输入流式解析，有界队列（建议最多8个投影），不能把1.6GB JSON及所有展开对象一次装入内存。
- 模型在隔离 worker 中常驻，多条记录复用。每条请求清理上一例状态，测试不同顺序下无跨样本污染。保留全局GPU互斥；其他知因进程占用时明确拒绝/等待，不偷偷并行启动模型。
- 启动/加载超时与单目标推理超时分别配置，沿用60秒作为首版保守默认，实际值写入manifest。加载计一次；逐目标耗时、等待、总运行耗时分别统计，不能直接与旧每槽冷启动p95混算。
- 超时/取消先杀进程树并确认回收，再释放互斥；常驻worker失效后可为后续新目标重建。当前失败尝试原样保留，不自动重试同一目标来挑成功值。未知异常/来源hash漂移/非法出站/日志无法持久化立即停止，延续Q-38/Q-39语义。
- 每条持久化 started/completed/failed/skipped，包含 run_id/input_id/方案/attempt_id/版本与耗时；断点不可覆盖旧结果。resume仅接续未开始的目标；崩溃时已started但无最终结果的目标标 interrupted/结果未知，单列，不默认为成功或自动重复。
- 恢复前核对来源、映射、模型、理由包、预算策略、源码与运行配置指纹。指纹改变创建新run；同配置允许恢复并保留分段运行环境记录。
- explore输出只标运行状态，如 COMPLETED、PARTIAL、STOPPED，另列质量 `NOT_EVALUATED`；不能把任务执行成功解释为质量合格。

## 5. 报告与“跑出结果”的验收

每次交付机器可读 JSONL＋汇总 JSON，以及可直接本机查看的 HTML 或等效报告；不要求用户写脚本才能理解结果。

1. **来源记录层：** 计划/扫描源记录数，解析失败、关联失败、无目标、排除与保留数；输出目标总数、唯一会话组数与共同来源重复数。不同层不能混为一个分母。
2. **目标×方案层：** 计划槽位＝成功建议＋合法拒识＋技术失败＋输入不适用＋明确跳过＋中断结果未知＋未开始；桶互斥、可对账。成功建议按任务/理由分布；拒识、缺材料、预算超限分开。
3. **覆盖与速度：** 可映射/可运行比例分别报告分子分母，按来源/自然语言/长度分层；冷启动、常驻单目标p50/p95、总耗时、目标/秒、GPU峰值和进程内存。不得仅对成功/短输入报告覆盖率或耗时。
4. **原因正确性：** 未人工审阅时不报告真实理由库覆盖、路由遗漏真值、准确率或错误具体建议率；已有人工标签时也需单独选择正式评测，不自动升格。
5. **案例查看：** 可按失败/拒识/超限/任务筛选并按固定seed抽取正常案例。默认报告仅保存ID/原因码/引用；用户主动本机查看时从受控材料关联上下文、答案、预测与原反馈，明确分栏来源，避免将原文复制到普通日志或可公开报告。查看行为记入暴露清单。

### 持续批量验证要求

- 每源100记录冒烟覆盖真实schema和错误分支；随后每源1000目标或全部可用目标（不足时说明）跑候选C，记录总量与对账。额外进行至少30分钟持续运行，若真实材料已跑完可用合成输入做耐久测试，质量与耐久统计分开。
- 零结果丢失、零重复完成、无泄露；验证中断/恢复及无标签启动。连续运行不能OOM或无限增长；报告真实显存/RSS起终点与分段峰值，不用三次成功冒烟代替。
- 吞吐与预计全量耗时由实测推算并标明记录数量和超限比例；不提前承诺每秒多少条。失败后先修复执行/内存路径，不自动租GPU、不升级依赖或扩大模型上下文。
- 长输入占比高时另提“材料压缩/窗口抽取”任务与新策略版本。首版可以完成运行并如实显示较低覆盖，不为了达到旧70%而挑短样本、截断后隐瞒或事后改阈值。
