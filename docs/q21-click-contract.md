# Q-21：完整点击重试契约与兼容

2026-09-27。沿用已签署 B1 v1、D-15 / H-06 与 Q-21 独立验收预期；映射 FR-01/11/13/14/15、TD-04/09/11。本页先定义实现约束，不代表结果签署。

- 显式 `whynote_click_id` 的范围仍为租户、用户、目标版本。新 UUID 表示明确的新点击；同 UUID（含重连）表示重试。
- 动作和 Outbox 仍同事务。为新点击登记展示 ID 并占用当前票据，与动作幂等登记同事务；等待浏览器时不持有数据库事务。
- Q-22 修订（2026-09-27）：预约事务提交后才采样菜单起点。`expires_at=0` 表示已预约、尚未持久化期限，此时重试只返回 `click_pending`。菜单发出与期限一次性写入并行，写锁等待不推迟或挤占菜单的 60 秒窗口；回调返回当刻判断单调/墙钟期限，随后数据库等待不重新判为超时。相同点击重试不能重新登记期限或替换票据。
- 期限写入失败时不报告原因成功；动作预约仍保留。进程在期限持久化前崩溃，0 值预约继续返回 `click_pending`，不猜测是否已经展示，也不自动重开；用户明确的新点击可替代该预约。完成结果仍从原响应事件恢复，不受该中间状态影响。无需 schema 迁移，旧正数期限沿用；旧代码会把 0 视为已到期，因此回滚仍须先停止 S0 流量。
- 进行中重试返回 `click_pending`，不新开菜单、不替换原票据。到期后返回 `ticket_expired`；被明确新点击替代时返回 `click_superseded`。重新操作须发起新点击，不把自动重试改成新 UUID。
- 已完成点击从对应展示的首条响应事件重建原返回值，保留原状态、展示回执与首次计时。即使之后有新点击、更正、服务实例重建，旧重试不追加事件或发送通知。返回的展示回执是原提交回执，不授予再次提交权限。
- 撤销优先：旧点击返回 `retracted`；新 UUID 可建立新动作。每次重试仍先核验宿主身份、归属与目标版本。
- 新增 `host_clicks` 是运行时去重索引，只存动作引用、幂等键摘要、展示 ID 和到期时间，不保存会话 ID、原文或密钥。响应事实仍在原追加事件中；不新增或改写事件语义。登记与响应分别持久化，响应提交后即使通知失败，重试也能重建结果。
- 旧数据库前向升级只创建索引表。旧显式点击没有展示绑定，不能猜测其完成结果：返回 `legacy_click_unavailable`，不弹菜单、不追加事件。用户明确发起新 UUID 后继续操作。旧无 ID 协议沿用原兼容行为，不宣称完整点击去重。
- 中断、断线或非法回调不释放同点击用于再次展示；现有票据最多有效 60 秒。重试不会导致原合法菜单失效。新点击仍可替代旧菜单；旧回调按原票据规则拒绝。
- 回滚到旧代码可读取所有原事件，保留新增索引表与审计数据；旧代码会恢复 Q-21 缺陷，因此仅允许停止 S0 流量后回滚。不得通过删除旧数据库/事件掩盖重复历史。
