### 单点踩入口（2026-09-28 用户明确更新）

本机测试改用一个“知因点踩 / 撤销”按钮，Laya 是知因内部原因分类模型。首次点击先将点踩和 Outbox 同事务提交，再直接请求本机 Laya 并展示未确认的原因分类；再次点击撤销，第三次重新建立点踩。推断不持有事务锁，推断失败或超长不撤销已保存动作。在途撤销、目标编辑、停用或换代后不展示旧推断。关闭三按钮展示，不再自动弹常规原因菜单；旧菜单、旧事件和确认历史保留。

每次有意点击带独立 UUID，同 click ID 的重试/重连只读取原动作结果，不再次翻转、不再次推断。不同点击在 SQLite 写事务内顺序切换；已有有效旧点踩的第一次新按钮点击为撤销。模型推测不写成用户确认，不复制原文到事件；数据库 schema 不变，新增 `toggle` 幂等操作使用已有表。研究指标仍关闭。回滚时恢复旧三入口配置和实现，保留追加事件。

## 使用

启动器、登录信息和独立数据库位于主项目 `var/local-chain/`，不进入 Git。页面 `http://127.0.0.1:8128`，Laya 使用已安装的 `http://127.0.0.1:8766`。刷新页面后，回答下只有一个“知因点踩 / 撤销”拇指向下按钮。首次点击立即保存点踩并展示 Laya 分类；再次点击撤销，第三次重新点踩和分析。已有有效旧点踩会直接撤销。模型返回当前为原因分类，不生成自由文本长篇解释；推测不等于用户确认。

较长答案可能超过 Laya 700 token 上限，届时提示失败；不静默截断。建议先要求 DeepSeek 用一两句话回答。Laya 输出质量尚未达标，本轮只验证连通和行为，不能把建议当正确标签。

### 长回答中断修复（2026-09-28）

本机发现云回答在约四秒、已收到 2,534 字符时中断。固定虚构长代码请求复现：SSE 累计 262,146 字节时触发原 256 KiB 上限，尚未收到终止原因及 usage。该限制误把逐 token 重复的 JSON 元数据计入过小的传输额度。

传输上限调整为 1 MiB；既有输出 1024 token、正文 64 KiB、60 秒、单并发及无自动重试保持不变。失败提示区分传输/正文限制、截断、超时、连接及校验失败；普通日志只记录固定错误代码，不记录供应商响应正文或异常内容。截断回答仍不发放反馈资格；已知 usage 按原规则结算，未知费用继续保留预占。旧失败及其预算不回写，不自动重放用户问题。此修复不改变事件和数据库 schema。

修复后同一虚构长代码请求完整读取 295,592 字节及 `finish_reason=length`、usage 60/1024，正确提示长度上限并结算 8,312 微元；未获得反馈资格。服务保留数据库重启后，浏览器新建虚构短请求自然完成，回执 `completed`，usage 42/12、结算 180 微元。核心 305/305、原生 77/77、Ruff 通过；新增传输超出旧限额的合法终止和超出新限额的拒绝用例，保留长度截断、无 DONE、超时、无效响应等用例。原有两个未知用量失败预占保留，供应商账单未核。元数据证据见 `qa/evidence/2026-09-28-local-chain/generation-fix.json`；本轮没有重做 Laya 质量评估或完整链路独立验收。

启动：主目录 `var/local-chain/start.cmd`（依赖保留的隔离工作树、固定宿主构建和原生运行环境）。停止 Open WebUI：`var/local-chain/stop.cmd`；Laya 独立停止使用 `var/laya/stop.cmd`。重启保留同一数据库和预算，不能重新 provision。登录账号与随机密码见 `var/local-chain/login.txt`；勿提交该文件。
