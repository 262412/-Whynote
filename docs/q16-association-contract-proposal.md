## 已冻结规则

| 决策 | 建议规则 | 影响与备选 |
| --- | --- | --- |
| 新关联权限 | 普通用户和管理员新建评分时，只能关联当前归属自己的 chat/message；开关两状态相同。客户端 ID 只作查询参数，只查身份与对象元数据，不为拒绝请求返回问答。不存在、已删除或外主体对象统一 404；结构非法 ID 返回 422。 | 不纳入共享聊天、跨租户评分或管理员代他人评分；如需要必须另立契约。评分作者仍取认证主体，不接受客户端 user_id。 |
| 更新与重绑定 | 评分作者及已验证的 chat/message 关联不可重绑定，包括移到本人另一聊天或通过清空 meta 脱离关联；冲突返回 409。仅更新评分内容时复核现有目标仍合法。管理员在导出开启时可按既有规则编辑内容，但不因此获得重绑权；管理员与目标/作者身份需明确核对。 | 如需允许重绑定，须另定义目标授权、原关联解除及并发语义。无关联评分继续可创建和编辑；后续首次绑定也需明确授权，不隐式接受。 |
| 无 chat_id 评分 | 保留现有独立评分语义；不参与聊天级清理。仅有 message_id 而无 chat_id 的请求返回 422。 | 历史不完整 meta 仍可读，不能自动补成可信关联。 |
| 可信关联证明 | 采用服务端维护的关联记录，记录评分 ID、作者、chat/message 引用及验证版本；客户端不能提供或覆盖验证标记。关联验证与评分写入同事务，删除依据该记录并复核作者与聊天归属。 | 单靠 meta 中新增布尔字段或仅在路由先查后写不能作为充分证明。本实现使用 Feedback 服务端列和 SQLite 写锁；仍需独立实现审查，不保存原始问答。 |
| 历史记录 | 旧评分默认“未验证”，包含作者与聊天看似一致的记录；不自动认定可信，不批量删改。聊天删除保留这些评分，输出不含正文的待审核清单，分别标记无关联、未知、矛盾或已删目标。只在独立批准的重新验证流程中升级可信状态。 | “同作者且对象存在就自动可信”会将旧客户端输入追认为授权事实，本候选不采用。保留不等于可复用作事实源/训练数据，也不构成合法留存期限决定。 |
| 删除路径 | 单条、批量、空集合、文件夹删除仅清理已验证且属于实际被删聊天所有者的关联评分；账号删除按既有账户范围删除该作者评分，绝不借伪 chat_id 删除其他作者记录。管理员独立评分 DELETE 权限保持另行核查。 | 对历史伪关联仅保留并登记待审核，不在普通聊天删除时隐式清除。活动库、备份/导出及设备历史副本分别报告。 |
| 失败与竞态 | 目标撤权/删除或更新校验失败：精确拒绝、评分和关联零变更；删除中任一步失败，同事务关联/评分/聊天变更回滚。重复删除不得扩大范围。 | 须有真实数据库交错、故障注入和重试用例，不能用单次先查后写测试宣称解决竞态。 |
