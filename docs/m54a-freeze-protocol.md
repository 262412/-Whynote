## 3. 独立标签操作规则（供确认）

1. 先在探索集核对任务、缺材料、多个问题、类别缺口，修订理由库。留出集按会话/共同来源/近重复组隔离，探索过的组不进入留出。
2. 标注界面/材料只提供预测允许看到的问题、目标回答及获准材料；隐藏A/B/C输出、置信度、生成结果、原评价和事后反馈。
3. 两名标注者独立判断defect/no_defect/unjudgeable，给出可支持的完整理由集合、参考任务与领域。理由库覆盖不到的问题保留defect及空理由集合，并在受控审阅表记录类别缺口。
4. 争议交裁决，记录原两份判断、分歧类型、裁决依据、reviewer_refs和adjudication_ref。UUID只是可追溯标识，不能单凭字段证明独立性。
5. 标签在查看预测结果前冻结、计算hash，原评价/用户原意作为分离材料保留；不回灌预测输入、不冒充本产品用户确认。
6. 模型输出之后的引文支持性/来源混淆审阅另存，不能改写已冻结的缺陷gold。现阶段live无可靠定位时仅类别展示，不能凭空评价“引文正确”。

可复用[现有标签验证](../src/whynote/replay_metrics.py)：input_id、review_origin=independent_adjudicated、两名reviewer_refs、adjudication_ref、partition=holdout、verdict、reason_ids、legacy_reason_codes、reference_task、reference_domain。
正式采集还需盲审过程、分组/来源、冻结时间与标签文件hash的外部记录；当前字段验证尚不证明这些事实。

## 4. 指标口径及待补实现

先逐例记录，再按来源/任务/语言/长度层汇总。总留出N、缺标签、无法判断、输入超长、缺材料、运行失败和拒识单列，不能从总流程分母消失。
A为旧八类Choice，B/C为逐理由判断；A/C只作整方案比较，B/C仍须相同输入与预算。不得仅凭“具体建议更多”选胜者。

| 评测问题 | 当前实现 | 冻结前处理 |
| --- | --- | --- |
| 理由库是否覆盖 | library_coverage：gold与library_ids相交的缺陷例/所有可判断缺陷例 | gold理由集合须完整；库外缺陷不能改标no_defect |
| 路由是否漏掉可用理由 | routing_omission：库有覆盖、实际有路由但最终候选无gold的例数/库有覆盖例数 | 当前分母含routing_unavailable例；需明确是否保留该口径，并同时报告运行失败与成功路由条件分母，避免稀释 |
| 初始路由与回退 | initial_routing_omission、reference_route_coverage已存在 | 分开初始与回退后覆盖、材料门控损失；不把缺原代码等同路由错误 |
| 候选是否命中 | candidate_hit：预测命中gold的例数/可判断缺陷例数 | 同时看拒识、覆盖和单候选损失 |
| 判断错误 | judgment_error目前为“有可用gold且运行成功但未命中”的例数/该条件总例数，包含unknown/no_match | 正式阈值需分开无依据选择、可判却拒识、选择了其他错误理由；当前字段不能直接解释为纯错误断言率 |
| 是否误导 | misleading：预测含gold外理由的例数/可判断且给出建议的例数 | 完整gold是前提；unjudgeable当前排除，另报其建议数及比例，不能据此宣称所有输出误导低 |
| 引用支持性 | 模板有原文匹配校验，但现有quality_metrics没有引文支持gold | 单独冻结人工相关性/支持性规则及分母；无引用标不适用，不能补零 |
| 错误、拒识、延迟 | 现有runner保留状态和分层计数 | 冻结重试归属、所有失败保留、运行顺序及总耗时口径 |

上述解释来自main固定源码。本轮未修改统计代码。指标拆分/新增报告字段需先确认口径，再以边界用例实施；保留旧报告语义和版本。
