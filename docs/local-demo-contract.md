# 本地反馈闭环测试宿主契约

状态：PRD FR-01、FR-10、FR-11、FR-13、D-11 至 D-13 与技术文档 TD-01/TD-04、Q-09/Q-10 的本地端到端验证切片。2026-09-26 核对飞书 PRD 修订 68、技术文档修订 10。此宿主仅使用虚构目标、临时测试身份和候选原因码；不是获批的客户端或生产身份系统。

## 本地请求与事件流程

`python -m whynote.demo` 只监听 `127.0.0.1`，并为每次启动创建随机测试会话和独立测试身份。浏览器访问 `/demo`，点击点踩后向已有动作 API 提交固定的虚构目标版本；动作和 Gate Outbox 先持久化。页面实际插入常规原因菜单并经过渲染帧后，以该会话向本地测试宿主的 `/demo/rendered-displays` 发送 `event_id`、新 `display_id`、`mode`、`ui_version` 和实际展示的原因码。宿主复核会话、当前目标权限和动作归属，再调用 `EventStore.record_display`。只在回执响应为 `actionable=true` 时启用原因提交。

用户选择原因产生 `reason_selected`，再次打开编辑菜单并更正产生 `reason_edited`；撤销点踩产生 `action_retracted`。选择与更正仍经过现有公共归因 API 的展示绑定、合法状态和幂等检查。展示事件只含原因码及展示元数据，不含问题、回答或测试会话令牌。

本地 `/demo/rendered-displays` 是测试用浏览器回执：同源页面持有临时会话令牌，只证明测试页面按流程发送了回执，**不能充当生产环境可信渲染证明**。正式宿主仍须提供真实身份、对象权限、短期展示票据、客户端渲染回执及防重放机制；`whynote.api:app` 默认继续拒绝业务请求。每次测试宿主启动使用不同主体；共用 SQLite 时，新实例不能读取、重试或修改旧实例的动作。此机制只验证临时身份隔离，不能证明 Open WebUI 的多用户、跨会话或跨租户权限。候选原因标签和页面文案只用于测试，不代表 taxonomy 或用户体验已获产品签署。无生产上下文、供应商调用、auto-attach 或自由文本。

## 兼容、失败与回滚

本切片不改事件或 SQLite schema。`POST /demo/rendered-displays` 的响应为 `display_id`、`receipt_status`（`current` 或 `historical`）和 `actionable` 布尔值。**已有回执的同内容幂等重试优先于当前可操作性校验**：当该展示仍为最新、动作有效且未有用户响应时，返回 200、`current`、`actionable=true`；被新展示取代、已消费或动作已撤销时，返回 200、`historical`、`actionable=false`，不追加事件。这个 200 只表示历史回执已入库，不能使原因提交成功；旧展示的归因请求仍返回 409。相同 `display_id` 内容不同返回 409；未登记的新回执若状态已撤销或不合法也返回 409。无会话或非本机请求拒绝，非当前身份/无目标权限返回 404，均不追加展示事件。`actionable` 是事务提交时的状态提示，后续原因提交仍逐次复核；并发撤销或新展示可以使它失效。

已存在的 `reason_displayed` 事件不修改，投影仍按 v3 重放；`EventStore.record_display` 的返回值由 `display_id` 字符串改为上述状态字典。本仓库唯一运行时调用方是本地测试宿主，已同步读取 `actionable`；其他直接调用该方法的测试集成需要按新返回值适配。原先只看 HTTP 200 的测试客户端必须读取 `actionable` 后才启用原因按钮。移除本地测试宿主不会改变既有动作/事件；生产代码无需启用它。
