## 来源与分母

- `self_natural`：本人自行决定聊天与是否点踩。原因由本人明确选择时属于self_report。
- `scripted`：按预设任务运行，即使同一人操作也单独统计，不掺入自然点踩率。
- `public_replay`：来源审查获准后评价既有公开回答；本人的评价属于evaluator，不冒充原提问者原因。公开自动标签保持其自动来源。

来源由受控会话清单在采集前登记并绑定，浏览器不能随请求改分组。修改登记保留版本，不事后重标以改善指标。事件的 `user_selected` 表示实际操作者选因；角色/研究来源须通过受控引用关联，公开标签不得直接写成该事件。

合格回答台账须记录**所有**符合S1-1资格的回答，包括没有点踩的回答；仅扫描Whynote动作无法得到自然点踩率分母。按实例、用户、会话、生成attempt与对象版本去重；重生成的新版本单列。来源缺失或回执不可信的回答不能静默归入自然使用。

报告固定宿主SHA、补丁hash、模型实际名称、连接配置/价格版本、UI/协议版本与观察截止时间。记录资格、分组和不透明引用；原文在受控正文库。实际模型别名可能升级，无法得到不可变模型版本时标未知。

## 固定对账案例（虚构开发输入）

| 输入案例 | 期望 |
| --- | --- |
| 自然组2个合格回答，其中1个点踩并选因 | 自然点踩率1/2；来源为self_report |
| 脚本组3个合格回答且全部被要求点踩 | 只计脚本组3/3；不能加入上行分母 |
| 公开回放2个案例，由本人选因 | evaluator；原公开标签不改写成用户确认 |
| 自然组一次中止/一次length截断 | 单列不合格生成，不进入合格回答分母 |
| 同click完成重试，重连再重试 | 动作、展示、响应与耗时记录不增加 |
| 窗后撤销、迟到原因、无计时上报 | 按B1/Q-20既定口径分列；缺失不填0 |
| 同回答多评价、同用户多会话 | 多评价不当多用户；参与者N=1 |

填写率以观察窗内明确选因的唯一动作/合格成功点踩计，主分母保留撤销项；展示覆盖、跳过/拒填/都不是/关闭/未响应分列。主动耗时与总耗时分别给有效数、缺失、中位数/p90。公开材料没有操作时间则不适用；没有模型建议的来源混淆指标不填0。
