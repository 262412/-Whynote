交接 JEV-HANDOFF-be2c07b7-4830-4bd8-a160-c33c2e1b3ac5；D-21 离线探索，基于 PR43 / 9246dd5。本分支依赖 PR43，未合并、未部署。

## 执行前冻结的范围

输入策略 `m55-full-input-windows-v1` 保留原 3000 目标及完整 state，未来反馈不进入 worker。2048/4096/8192 的 state 上限分别为窗口减260，总序列不超过窗口，字节上限为已有 IPC 的1MiB传输边界。这些是本轮研究参数，默认值、正式样本量及阈值仍待决策；应用700/1024/8192限制不变。

先算三档理论覆盖，再实测。短例与窗口验证优先；不先删历史。固定6个合成配对案例（有/无拒绝、满足/违反明确要求、原先要求保留接口/未要求保留），对原问题与一次明确措辞+中性标签修正做同输入比较。另在三窗运行短例回归、每源每长度档最多1个真实长例，以及约1800/3800/7800 token的合成约束位置探针。实际数量按入选清单报告；这是工程诊断样本，不是批准的质量评测样本。

逐 token 比对完整问题、选项、正文与SDK编码及实际forward输入。保留路由、所有原始概率与显式标签映射；不以跨问题yes最大值输出主要理由。缺少原代码不能据接口理由生成建议。无独立标签的真实长例质量为NA；合成配对预期不是正式gold。

仅一轮问题定义修正。如果明确短例仍明显误判，停止Laya调参，准备同批Jev对照并等待API/费用/出站数据授权。若仅长例失败，建议Jev优先承担长输入。历史选择/分段只能在窗口结果之后另行决定；不得以压缩掩盖判别失败。

沿用源到期门控（读取前、加载后、IPC发送前）、固定模型/SDK、机器互斥、AppContainer无网络和Job回收。原批次/历史失败不覆盖；普通日志及Git仅保留ID、摘要、数值和合成内容。

## 结果与去留决定（2026-09-30，作者工程验证）

**停止继续围绕Laya调参；下一步为同批Jev对照，等待新的API、费用及数据出站授权。** 扩窗解决了部分覆盖问题，但一次明确问题措辞/中性标签修正后，短输入仍有明显误判，不满足“短输入可靠、仅长输入失败”的分支。本轮没有做历史裁剪或分段，也不将4096设为默认值。

### 判别及路由

原标签`yes/no/unknown`，明确版`A/B/C`分别对应缺陷存在/不存在/材料不足。选择值已核对SDK按选项顺序解码及返回概率argmax；没有反转yes/no。实验同时改写问题并换中性标签，只能说明这组修正的整体效果，不能分离两者贡献。

- 6个短配对的指定缺陷：原版1/6符合预期，明确版5/6；三窗结果一致。这是合成诊断符合数，非正式准确率。明确版仍把允许自由改写接口判为违规；对正常数字回答也会额外判不必要拒绝，不能只看指定缺陷就宣布可靠。
- 首轮已知拒绝反例R09（完整教程）、R42（翻译）、R44（语气改写）仍被明确版判为不必要拒绝；R28的拒绝误判消失。R12仍在没有保留接口要求时判接口违规。R25语言切换仍路由为代码改写，简单泡茶任务也被路由为代码改写。R10本轮检查的是拒绝而非原报告的答非所问，因此不声称已复测其全部原问题。
- 三档长探针的满足要求/违反要求对均判缺陷存在，未区分阴性；该结果支持退出，不支持以更大窗口继续运行全量。
- 本轮绕过路由候选筛选逐项诊断，所有分数保留为原始模型响应，`primary_reason=null`。原代码/事实参考不足时不生成建议；不把模型对缺材料的yes当候选。参考反馈及本次预期不进入worker。没有阈值搜索、跨问题概率排序或第二轮问题调参。

“完整教程被判拒绝”在证明输入未截断后仍存在，所以不能归因为原700token门槛。是否有其它潜在模型/SDK问题仍需外部模型对照；本轮不能证明整个SDK无缺陷。
