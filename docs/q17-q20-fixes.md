## 修复及兼容

| 问题 | 行为与证据 |
| --- | --- |
| Q-17 | 宿主前端每次明确点击生成 `whynote_click_id` UUID，传给固定 S0 Action。该次请求重发保留同一 ID；撤销后新点击有新 ID。核心默认幂等规则不变：旧请求仍返回旧已撤销动作；新点击产生新 event_id/Outbox，当前有效意图仍跨会话复用。新增回归覆盖旧点击重试不弹新菜单、新点击和跨会话复用。 |
| Q-18 | 都不是、跳过、拒填、关闭/取消使用各自准确通知；只有提交原因使用“反馈与原因已记录”。原因保留/清空语义不变，五条无原因通知验收全部保留。 |
| Q-19 | 只对浮点数检查 isfinite，整数用数值界限比较，避免超大整数转 float 溢出。非法可选计时记录 invalid_duration/空值，反馈仍保存。响应同键重试按对象、操作、展示和原因判定一致性；可选计时变动不定义新意图，也不覆盖第一次测量。改变原因/操作仍 409。旧幂等行通过原追加事件核对，不迁移或重写旧数据。 |
| Q-20 | 增加 `retracted_action_count`：截至 as_of，固定 cohort 内已撤销的唯一动作数，含窗后撤销。原窗口状态、历史 as_of、固定分母均不变。 |

无 click ID 的旧宿主调用兼容：同一写事务内，仅在原动作已撤销时按持久化旧 event_id 推进请求键代次；活跃时仍复用，未随机化服务端重试键。旧协议无法识别跨撤销边界的延迟重发与新点击，因此完整请求区分要求部署本 PR 的前端补丁；不宣称旧客户端具备该能力。普通 HTTP API 不启用此兼容选项。没有新增表或修改历史事件。

统计单位澄清：`response_action_counts_in_window` 为每种响应涉及的唯一 event_id 数；行内 `response_counts_in_window` 为该动作发生的操作次数。重复更正两次仍是一个动作，未放宽独立 QA 数量断言。
