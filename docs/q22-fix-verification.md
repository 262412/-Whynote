## 基线和修复

main `e15a0fe` 已由外部合入 PR #22，本轮未执行该合并。在空闲、干净的 QA 工作树继续 PR #23 / `codex/qa-q21-retest`，基线 `9e001e9`。原样扩展验收复现 25 通过、2 失败：实际写锁等待约 0.8 秒后，受控菜单时间 59.5 秒被拒绝。未修改独立失败用例或历史报告。

这是 PR #22 将时钟移至预约事务前引入的回归。本次调整：

1. 显式点击的动作、Outbox、点击预约和当前展示票据仍同事务；兼容路径仍保留原预约流程。两条路径在预约事务**提交后**才启动菜单时钟。
2. 显式预约先存 `expires_at=0`，表示期限尚未发布。菜单回调与期限的一次性持久化并行，数据库锁不覆盖浏览器等待；重试不能续期或替换票据。
3. 回调返回时立即记录是否超时；等待期限落库和后续数据库操作不会把已按时到达的响应改判过期。墙钟和单调时钟的 60 秒边界均保留。
4. 期限写入失败会报错，不假报原因成功；动作预约保留。如果进程在发布期限前崩溃，重试保持 `click_pending`，明确新 UUID 可替代该预约。这个中间状态不猜测展示事实，也不自动重开。

兼容、失败恢复和回滚见 [点击契约](q21-click-contract.md)。不改 schema 或事件版本，不修改旧正数期限和旧事件。回滚须先停 S0 流量：旧代码会把 0 值预约当作过期，且恢复 Q-22。
