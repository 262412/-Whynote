## 2. 两条数据流与出站控制

1. 浏览器以宿主认证会话发聊天请求；宿主复核实例、获准用户、登记会话、所选模型及消息分支。构造上表限定的历史后，经预算预留才调用唯一 provider。浏览器提供的用户/租户/资格标记不可信。
2. provider 收到系统提示、选定的历史问答、本次问题、生成参数及服务端 API 认证；还可能看到网络地址等通信元数据。Whynote 原因、反馈事件、邮箱/姓名、会话 ID 不作为调用参数或自定义用户头发送。
3. 宿主保留聊天正文及生成状态；Whynote 仅保留不透明对象引用、HMAC版本、动作/原因与测量元数据。点踩或选择原因不会调用聊天 provider，也不会启动原因推断。
4. 默认关闭标题、标签、后续问题、检索查询、自动补全等后台生成及图片、音频、工具功能。禁止任意模型、个人直连、备用 URL、重定向和透传代理绕开同一出站入口。需同时检查持久化有效配置和实际请求，环境变量并非充分证据。
5. 宿主可能将 provider 错误正文写入日志，S1-2 须屏蔽原始错误体与请求内容，只记录受控错误码、状态和引用；不把密钥/原问答写入日志、队列或普通事件。

## 3. 回答资格与版本

**建议只接受服务端确认自然完成并稳定保存的非空文本回答。** 流式中、用户中止、断流、超时、provider错误、空输出、`length` 截断、内容过滤、工具调用均不合格；可以另记生成失败计数，不伪造成功点踩分母。

固定 Open WebUI `8bd8b4fac5e059578ac0c74b3c18d11139f88b7d` 的 `utils/middleware.py` 在正常结束和取消路径都写 `done=True`（约6559/6627行）；`routers/chats.py:update_chat_by_id` 允许归属用户更新聊天 JSON。因此 `done`、客户端内容或普通 chat JSON 都不是可信生成完成证明。

S1-2 须在宿主服务端生成终态处建立最小可信回执，待回答持久化成功后确认资格；暂未实现，不能只放宽 S0 fixture 判断。回执绑定：实例、认证主体、chat/message/parent ID、生成 attempt、允许模型、正文及父消息版本的 HMAC、可信终态、保存完成时刻和配置版本。保留引用/摘要，不复制正文。HMAC包含父消息内容与当前回答的必要字段；不以可猜测正文的无密钥哈希替代。

- 回调前及提交原因前都核对所有权、会话准入、当前父消息/回答版本和可信回执。删除、撤权、编辑任一正文或重生成使旧回执失效；新生成使用新 attempt。
- 相同目标版本的点踩/原因沿用 manual-v1 与 Q-21 明确点击 UUID；同一完成 click 重试不重开菜单、不追加事件或计时。新的明确点击允许更正。
- Q-22 的起点在预约提交后，期限在回调任务内捕获；真正超时、旧展示替代及撤销保持拒绝。不要让生成时限覆盖反馈时限。
- 云服务故障不影响对先前合格回答的反馈。首次拒绝不得留下动作/Outbox；动作已受理后发生撤权/删除则不追加非法原因，既有合法动作依删除/撤销契约处置。
- 现有 S0 `s0v1`、`s0t1` 与事件保持原样。拟新增 `s1v1` 版本空间、独立配置和入口；新增回执存储、迁移与删除规则在 S1-2 提交前补齐。历史无回执对象不自动升级为合格。

## 4. 100 CNY 费用边界

实际调用前应实现一个覆盖全部允许聊天调用的本地预算预留检查；此项属于本次云聊天准入，不声称交付 M5 推断预算平台。不能仅配置 `max_tokens` 或查看供应商余额就宣布具有硬上限。

- 固定计价版本与保守汇率；按最终出站消息的可靠输入上界、最大输出和最高适用费率预留。没有可靠计数/上界、价格或汇率时拒绝调用。
- 同事务判断 `已结算 + 在途/未知预留 + 本次上界 ≤100 CNY` 并创建请求记录；跨重启保留账本，只放行已预留请求。
- 响应提供可信 usage 后结算；超时、断流或 usage 缺失保留最坏预留，人工核账后才释放。取消本地等待不等于供应商没有计费。
- 费用到顶、价格变化、未知结果或异常并发阻止新生成；已有回答仍可反馈。严禁通过切换 API key 或重启绕过累计预算。
- 如用户改用供应商可验证硬限额，则单独记录其适用项目、其他调用与超限行为；预算告警不能充当硬限额。

运行 `python -m qa.s1_mock_provider --port 8126`，仅监听 `127.0.0.1`。Base URL `http://127.0.0.1:8126/v1`；模型 `whynote-s1-synthetic`；认证为工具公开的虚构 token `s1-local-synthetic-not-a-cloud-key`。不能填真实 API key。
