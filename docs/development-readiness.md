# 开发决策与下一步

## 已核对的基线

- 产品名为知因・Whynote。当前 GitHub 仓库在首次拉取时为空，因此本切片建立独立 Python 包。
- 技术开发文档 v0.1 的文内基线写作 PRD 修订版 60；本次飞书读取的 PRD 实际修订号为 66。实现优先采用当前 PRD 的产品行为与技术文档中一致的安全边界，差异仍需产品评审。
- TypeSafe 当前公开 OpenAPI 定义 `POST /v1/systemone`、`GET /v1/models`，响应包含实际 `model`、`answers` 和 `usage`。目前没有账户凭据或可用模型清单，未发起真实推断。

## 本切片的工程边界

1. 动作是独立事实，`event_id` 是聚合标识，`record_id` 是每条追加事件的标识。客户端重试使用按租户和用户范围哈希保存的 `Idempotency-Key`。
2. HTTP 身份与目标权限由宿主平台注入；未配置时拒绝业务请求。目标对象必须有不可变 `object_version`。
3. 动作事件与 Gate Outbox 同一事务提交。事件表只追加，当前状态由确定性 reducer 重建。
4. Gate 由可信策略输入授权、场景、抽样、预算四项结果。未获得可识别的抽样概率时不生成 IPS 权重。
5. 当前允许 Gate 后也拒识，因为尚无经批准的上下文快照、加密/删除机制、预算账本与供应商数据处理协议。自动附加和自由文本映射始终关闭。
6. `candidate-v1` 原因码仅是文档提出的候选 taxonomy；不能视为已冻结的 gold 标签定义。

## 下一开发切片的验收顺序

1. 对接真实鉴权与对象归属，并用越权测试确认租户隔离。
2. 评审数据流后实现白名单快照、脱敏、受控加密引用及删除演练；Gate 拒绝路径零上下文读取。
3. 接入预算预占、取消释放和对账，完成 Outbox 消费幂等与撤销竞态测试。
4. 用脱敏离线样本实现 Jev/本地分类器适配、独立校准、OOD 和候选确认；独立 gold 与中文切片评测通过后再进入 shadow。
5. 由产品、隐私、安全和算法分别批准 UI 文案、抽样权重和 auto-attach 策略；自动附加仍需单独开关与灰度审批。
