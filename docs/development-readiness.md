## 1. 当前起点与目标

2026-09-28产品复核main 52ac4db21e9f83ae50f17f7a1a4c2c4984540997：PR #30～34已合入。DeepSeek、Open WebUI、Laya及单按钮点踩/撤销已经接通；用户已实际试用，反馈基本分类可用但遇到无法归类案例，尚无量化效果结论。当前只传直接父问题与目标回答、显示一个模型分类，不采集原因确认或建议展示回执；S1-3研究记录仅mock。本轮按用户要求，已交付任务退出当前待办，保留历史证据；下一阶段为M5-0a案例/三源映射→M5-0b任务理由包→M5-1三方案回放→M5-2模板建议与确认记录。生产上下文、auto-attach、自由文本SLM和训练导出仍关闭；完整FR、独立验收及适用签署不由合并代替。上述为产品计划轮的核对结论；本研发轮合成切片状态见下方 M5-0a，未执行真实模型或语料测试。

研发输入：已读取并核实 PRD 310 / 技术文档 312。[PRD](https://my.feishu.cn/wiki/XG6SwutL0i3fyWkwmhScEEB86Gg) / [技术文档](https://my.feishu.cn/wiki/GuphweJs3iWwBRkBDjlcljA16bh)。本轮开始 M5-0a 合成映射实现；研发证据见[交付记录](m5-source-delivery.md)，真实数据准入与独立验收保持单列。

**本阶段目标：** 提高理由对实际问题的覆盖，让用户用更少补充说明确认具体问题。用户说“基本分类可用、无法归类情况较多”是N=1试用线索；尚无失败比例、案例集或独立标签，不能先假定都是类别不足。

本轮产品安排：以任务类型为主、领域为补充，保留通用理由和跨任务回退；从无法归类的实际案例决定扩充，不预建穷尽领域的大理由库。先覆盖代码改写，其他高频任务由审阅证据决定。保留用户明确要求、否定词、材料/回答版本及来源，关键词仅作辅助，不重复堆关键词。当前本机入口没有传此前对话或独立材料，新增读取须先冻结授权和最小上下文契约。动态建议采用固定模板＋可核对原文/代码块引用＋分类判断，不使用自由文本生成；无法定位就只显示类别，不编造行号、未执行的报错或用户动机。模型推测与用户确认分开。固定Laya做A/B/C产品方案回放；仅出现具体适用性缺口才考虑替代模型。

## 4. 回放协议与产品指标

M5-1使用同一固定Laya评估三种方案：A当前八类；B先选单一领域、仅在该领域理由中选；C任务理由＋通用理由＋跨任务回退。B/C共用同一冻结理由库以比较路由；另用人工审阅的任务/领域参照计算路由遗漏，区分候选库覆盖和模型选择错误。样本、上下文预算/窗口、选项顺序规则、模型/criteria/理由库版本、随机种子与输出数量在运行前固定；记录多阶段调用总耗时，拒绝/超长/错误不删出分母。模板/引用质量另分报，不把模板新增信息混入纯路由比较。先探索集修订理由包，再锁定独立留出集；同会话/近重复及WildFB/WildFeedback共同来源不得跨集合。预测输入不含事后反馈、标签、修改答案和未来轮次；给定反馈分类另列用途。三数据源分开统计任务/语言/长度/来源，公开评价不直接当用户原因或gold；独立裁决标签到位才算质量指标。样本量、接受阈值、观察窗和停止规则事前冻结；无真实操作不能计算填写耗时或用户价值。

| 指标 | 口径 |
| --- | --- |
| 理由库覆盖 | 经审阅可判定且含问题的样本中，存在至少一个能表达已标问题的理由的比例；分母、无法判断及无缺陷样本另列。 |
| 路由遗漏 | 理由库本来覆盖的样本中，路由后正确候选被排除的比例；与人工参照任务/领域的候选结果对照。 |
| 候选命中/误导 | 冻结候选数下，候选是否表达审阅问题、是否提出无依据原因；多问题标签、无法判定和非原用户评价分别报告。 |
| 定位/模板 | 引用是否精确对应原文与对象版本；引用是否支持建议分别评，不能以字符串存在代替因果依据。 |
| 运行覆盖与成本 | 全量入样的有效输出、超长拒绝、错误/拒识及缺失，分阶段与合计p50/p95；失败不能从分母消失。 |
| 展示与反馈 | 建议生成、客户端渲染回执、有效响应分层；是/不是/都不是、跳过、关闭、未响应、更正分开，动作/推测撤销分开。 |
| 用户成本/价值 | 实际补写需求与必要补充次数、主动耗时/总耗时、可定位/可处理价值；对比常规菜单，保留缺计时和自评偏差，公开语料不产生此指标。 |

独立原因审阅需有标签规范、分歧及裁决记录；用户自己选的原因、评价员答案质量、自动标签和模型推测分别保存。采集前定样本量/时长、候选数、观察窗、阈值、排除与停止规则；缺独立标签不补造准确率。个人反复聊天仍N=1；公开数据不能提供本工具的真实补写率、填写耗时或业务价值。

## 5. 展示、确认与兼容契约

M5-2a先冻结最小事件契约：建议生成与客户端渲染回执分开；渲染回执只证明客户端报告渲染，不证明用户看见。建议/候选ID、主体、对象/回答版本、event_id、display_id、候选顺序及模型/理由包/模板/UI版本绑定，事件只存引用和必要元数据。是这个问题：显式确认指定建议；不是：否定指定建议，不撤销点踩、不自动清空此前用户原因；都不是：拒绝本次整组候选，若复用manual-v1的none_matched则沿用清空当前原因的既有语义并在UI明确，改变语义须新契约/兼容规则。跳过、关闭、未响应、无原因及unknown分开；0点击不等于确认。更正、动作撤销、推测撤销分别追加，旧事件不回填模型确认。覆盖重复回执/点击、旧菜单、撤权/删除/换版/在途撤销、研究停用和报告只读。当前这些模型建议记录未实现，旧人工菜单事件不能冒充。

`reason_id/reason_family`、任务包、建议/引用和各版本字段均为拟议契约，研发前冻结命名/枚举/迁移与回滚；不把新细类别强塞旧八类或改变已有用户选择含义。新版停止时恢复已有常规原因路径，保留追加事件与旧投影可读性。

## 6. 保留的验收事项与阶段边界

- **现阶段GO：** 案例审阅、三个适配器与合成管线、小任务理由包、离线协议、最小记录契约；逐源获准后进行小批本机回放。用户既有本人DeepSeek+Laya联调授权及已签v1/100 CNY边界继续有效，不再列“安装模型/首次接通”为任务。
- **后续条件：** 新模板/确认记录真实试用依赖M5-2a契约、离线门槛及受影响数据/权限测试；研究记录用途、留存、删除/导出/备份需覆盖新增元数据。现有mock限制不能直接移除。
- **仍需收尾：** 当前本机链路的独立QA、非作者批准及适用结果签署，供应商留存/训练/删除证据缺口和新范围副本验证。已有局部技术通过保留，未签项不因旧任务移出待办而自动关闭。
- **暂不进入：** 多供应商模型竞赛、穷尽领域理由库、自由文本生成/SLM、生产上下文、auto-attach、训练导出、未经另定范围的志愿者研究。先证明补写负担与误归因有改善，再扩任务范围。
- **停止条件：** 越权、敏感正文/密钥泄漏、未经准许出站、非法重复写入立即停受影响路径；未达到预设效用/误导门槛则保留常规菜单并修订/收窄方案，不事后改阈值宣布通过。
